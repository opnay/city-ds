# Outline Frame

Outline Frame은 atom·molecule의 Surface 축에서 폼 사용자가 **값을
입력·검색·선택·증감하는 프레임형 컨트롤**에 적용하는 outline 계열입니다. 하나의 둥근
외곽선 안에 값 영역과 보조 요소를 배치하고, 서로 독립적으로 조작되는 영역은 내부
구분선으로 나눕니다.

컴포넌트의 기능이 달라도 같은 크기에서는 동일한 외곽 높이·radius·stroke·상태 표현을
사용하십시오. 그림자나 중첩된 면보다 외곽선과 구분선으로 구조를 드러내는 것을 기본으로
합니다.

> 대표 구성은 패턴 설명과 회귀 비교를 겸합니다. 같은 `size`의 외곽 높이나 프레임 표현이
> 다르면 컴포넌트별 예외가 아니라 구현 결함으로 판단하십시오.

## 크기 계약

`size`는 단일 행 Outline Frame의 **외곽 border-box 높이**를 의미합니다. border와 padding은
이 높이에 포함하며, 내부 input이나 segment가 프레임 높이를 다시 늘리지 않아야 합니다.

외곽 높이는 공통 [Control Size](?path=/docs/디자인-패턴-size-control-size--docs) 계약인
`sm/md/lg = 32/36/40px`를 사용합니다.

같은 `size`의 Input, SearchField, Select, Combobox, NumberField, DateField, DatePicker는 한
줄에 배치했을 때 위아래 경계가 일치해야 합니다.

단일 행 Outline Frame의 텍스트는 `sm/md/lg = 12/14/14px`, line-height는
`16/20/20px`를 사용합니다. Surface나 focus·invalid 상태가 바뀌어도 Typography는
달라지지 않습니다.

Outline Frame의 `32/36/40px` 높이는 Shape 축의 regular rectangle 단계이므로 모두
`--city-radius-sm`을 사용합니다. 내부 padding이나 segment 수가 달라도 외곽 radius는 바뀌지
않습니다.

## 구성 규칙

- **Plain**: Input처럼 하나의 값 영역만 외곽선으로 감쌉니다.
- **Affixed**: InputGroup처럼 값의 일부인 접두·접미 요소를 같은 프레임에 둡니다. 접두 텍스트의
  시작선은 값 텍스트와 맞추고, 접미 텍스트의 끝선은 Select·Combobox·DatePicker의 말단
  아이콘 끝선과 맞춥니다. Addon과 값 텍스트 사이의 간격은 방향과 크기에 관계없이 4px로
  유지합니다.
- **Segmented**: SearchField, Select, 단일 Combobox, NumberField처럼 말단 affordance나 독립
  조작 영역을 내부 구분선으로 나눕니다. 지우기는 값 편집에 딸린 보조 액션으로 두고, 검색
  실행·목록 열기처럼 역할이 바뀌는 말단 요소만 전체 높이 segment로 구분합니다.
- **Expandable**: 다중 Combobox처럼 내용이 늘어나는 경우 크기 토큰을 `min-height`로 사용하고
  동일한 radius·stroke·상태 규칙을 유지합니다. 입력·전체 지우기·목록 열기는 단일 행 높이의
  상단에 두고, 선택된 chip은 수평 구분선 아래의 별도 band에서 줄바꿈합니다. 선택값이 없으면
  chip band와 구분선을 함께 숨깁니다.

외곽선은 컨트롤의 전체 경계를, 내부 구분선은 독립 조작 역할이나 전체 동작을 대표하는 말단
affordance의 경계를 나타내야 합니다. 장식만을 위해 영역을 나누지 마십시오.

## 상호작용 위임 규칙

Segmented 프레임은 hit target 구성에 따라 두 방식으로 구분합니다.

- **Unified Trigger**: Select처럼 프레임 전체가 하나의 동작이면 값 영역과 말단 아이콘 영역을
  하나의 Trigger로 구현합니다. 프레임 어디에서 hover·active·click이 발생해도 말단 segment가
  동일한 상태 피드백을 표현하고 같은 동작을 실행해야 합니다. 말단 아이콘은 affordance일 뿐,
  별도 버튼·탭 정지점·접근성 동작으로 만들지 않습니다.
- **Independent Segment**: SearchField·Combobox·DatePicker처럼 값 편집과 말단 동작이 다르면
  각 영역의 hit target과 hover·active를 분리합니다. 값 영역의 상호작용이 말단 액션을 대신
  실행해서는 안 됩니다.

두 방식 모두 focus·invalid·disabled는 전체 프레임 상태로 표현합니다.

## 상태 규칙

- Independent Segment의 hover와 active는 실제로 조작되는 segment에 적용하십시오.
- Unified Trigger의 프레임 hover와 active는 동작을 대표하는 말단 segment에 위임하십시오.
- focus와 invalid는 전체 프레임의 상태로 표현하십시오.
- disabled는 값 영역과 segment가 하나의 비활성 컨트롤로 읽혀야 합니다.
- 포커스 링과 상태 stroke가 외곽 크기나 주변 배치를 바꾸지 않아야 합니다.

## 적용 범위

적용 대상은 Input, InputGroup, SearchField, Select, Combobox, NumberField, DateField,
DatePicker처럼 사용자가 값을 직접 편집하거나 선택하는 프레임형 컨트롤입니다.

Button, Checkbox, RadioGroup, Switch, Toggle은 폼에서 사용할 수 있어도 Outline Frame 대상이
아닙니다. 이들은 값을 담는 프레임이 아니라 액션이나 선택 상태 자체의 형태가 핵심이기
때문입니다. Textarea와 다중 Combobox는 외곽 표현을 공유하지만 고정된 단일 행 높이는 적용하지
않습니다. Select와 Combobox의 popup도 별도의 floating surface로 다룹니다.

## 검토 기준

1. 같은 `size`의 단일 행 컨트롤 외곽 높이가 일치합니까?
2. radius, stroke, 배경과 좌우 여백이 같은 시각 계열로 보입니까?
3. 값 텍스트의 시작선과 말단 아이콘의 끝선이 컴포넌트 사이에서 일치합니까?
4. 내부 구분선이 독립 조작 역할이나 말단 affordance의 경계를 설명합니까?
5. Unified Trigger는 프레임 전체 동작과 말단 segment 피드백이 동기화됩니까?
6. 말단 아이콘이 불필요한 버튼이나 탭 정지점을 추가하지 않습니까?
7. focus, invalid, disabled 상태가 segment가 아니라 전체 프레임 기준으로 일관됩니까?
8. 내용 확장형이 기본 높이보다 작아지지 않고 자연스럽게 늘어납니까?
