## 키보드와 포커스

마우스 없이 실제 작업을 처음부터 끝까지 완료할 수 있어야 합니다. 버튼, 링크, 입력은
네이티브 의미를 유지하고, 합성 컴포넌트는 제공된 Trigger와 Item을 사용하십시오.
`div`에 click handler를 붙여 대체하지 마십시오.

- Tab과 Shift+Tab으로 논리적인 순서로 이동하는지 확인하십시오.
- Enter와 Space가 각 control의 예상 동작을 수행하는지 확인하십시오.
- 열리는 Menu, Dialog, Drawer, Popover에서 포커스가 이동하고 닫은 뒤 트리거로
  돌아오는지 확인하십시오.
- 현재 페이지, 선택, 눌림, 확장 상태를 색상만이 아닌 텍스트와 semantic state로
  알 수 있게 하십시오.

## 레이블, 설명, 오류

입력에는 보이는 Label을 우선 사용하십시오. Input, NumberField, Select와 입력형
Combobox는 외부 `Field.Label`을 사용하고, SearchField, DateField, DatePicker는 각
컴포넌트의 Label을 사용합니다. 레이블을 보일 수 없는 경우에만 `aria-label` 또는
`aria-labelledby`를 제공하십시오. 도움말과 오류도 같은 Field 문맥의 Description과
Error에 두어 control과 연결하십시오.

```tsx
import { Field } from '@opnay/city-ds-react/field';
import { Input } from '@opnay/city-ds-react/input';

<Field.Root invalid>
  <Field.Label>배포 이름</Field.Label>
  <Input />
  <Field.Description>소문자, 숫자, 하이픈만 사용하십시오.</Field.Description>
  <Field.Error match>배포 이름의 형식을 확인하십시오.</Field.Error>
</Field.Root>;
```

아이콘 전용 Button, Toggle, 메뉴 항목에는 각 요소의 목적을 설명하는 접근 가능한 이름을
제공하십시오. placeholder와 Tooltip은 레이블의 대체 수단이 아닙니다.

## 동적 피드백

현재 화면에서 변한 상태는 사용자가 놓치지 않게 알리십시오. `Alert`의 tone에 맞는 기본
live 영역을 존중하고, 필요할 때만 `aria-live`와 role을 명시적으로 조정하십시오.
`Toast`는 짧은 결과에, 화면에서 해결해야 하는 오류는 `Alert`에 두십시오.

진행률을 계산할 수 없으면 `Progress`의 indeterminate 상태를 사용하고, 계산할 수 있으면
값과 의미를 함께 제공하십시오. Skeleton은 장식적 로딩 자리이므로 실제 콘텐츠의 레이블을
대신 전달해서는 안 됩니다.

## Dialog와 다른 오버레이

Dialog, AlertDialog, Drawer, Popover, Tooltip은 화면 밖의 정보를 가릴 수 있습니다.
필요한 정보와 다음 행동을 overlay 내부에 모두 두고, 닫기와 취소를 명확히 구분하십시오.
특히 파괴적인 action은 `AlertDialog`에서 결과를 설명하고 취소를 제공하십시오.

한 작업에 overlay를 중첩해야 한다면 흐름을 다시 나누는 편이 좋습니다. Tooltip에 오류,
필수 레이블, 긴 설명을 숨기지 마십시오. 보조 설명은 키보드와 포인터 모두에서 접근할 수
있어야 합니다.

## 모션, 대비, 작은 화면

패키지는 `prefers-reduced-motion: reduce`에서 Skeleton shimmer를 멈춥니다. 앱에서
추가하는 이동·자동 재생·대형 전환도 같은 선호를 존중하십시오. 상태를 애니메이션으로만
전달하지 마십시오.

텍스트와 경계는 테마별로 충분한 대비를 유지하고, focus ring을 제거하거나 배경과 같은
색으로 덮지 마십시오. 확대, 긴 한글 문구, 320px 수준의 좁은 화면에서 overflow를
확인하십시오. Table은 `DataTableRegion`의 스크롤 힌트와 레이블을 사용하십시오.

## 소비자 검증 체크리스트

- [ ] light, dark, system에서 텍스트·경계·focus ring을 확인했습니다.
- [ ] 키보드만으로 폼 제출, 필터 변경, overlay 열기·닫기를 완료했습니다.
- [ ] 모든 입력에 레이블, 필요한 설명, 오류와 복구 방법이 있습니다.
- [ ] 아이콘 전용 control과 ToggleGroup에 접근 가능한 이름이 있습니다.
- [ ] 로딩, 빈 결과, 실패, 성공, disabled와 좁은 화면의 overflow를 확인했습니다.
- [ ] Toast, Alert, Progress 등 동적 상태가 역할과 live feedback을 통해 전달됩니다.
- [ ] 브라우저 확대와 보조 기술에서 읽기 순서와 링크·버튼 역할을 점검했습니다.
