# Control Size

Control Size는 atom·molecule에서 사용자가 읽고 조작하는 **단일 행 Control의 외곽
border-box 높이**를 정의하는 Size 축입니다. 컴포넌트 타입이나 Surface가 달라도 같은 `size`는
같은 높이를 사용합니다.

border와 padding은 이 높이에 포함합니다. 내부 텍스트·아이콘·segment가 외곽 높이를 다시
늘리지 않아야 합니다.

Button과 Input은 Surface가 다르지만 같은 `size`에서 위아래 경계가 일치해야 합니다. 이 비교는
각 크기의 실제 렌더 높이를 사용합니다.

## 적용 규칙

- 단일 행 Control은 `size`에 해당하는 높이를 정확히 사용합니다.
- Textarea·다중 Combobox처럼 내용이 늘어나는 Control은 같은 값을 `min-height`로 사용합니다.
- Solid·Outline·Ghost 같은 Surface와 tone·상태는 같은 `size`의 높이를 바꾸지 않습니다.
- font-size와 line-height는 [Control Text](?path=/docs/디자인-패턴-typography-control-text--docs),
  radius는 [Radius](?path=/docs/디자인-패턴-shape-radius--docs) 계약을 따릅니다.
- 시각적 외곽 높이와 접근 가능한 hit target은 별도 계약입니다. 작은 시각 Control도 필요한 경우
  레이아웃을 바꾸지 않는 확장 hit area를 사용합니다.

## 적용 범위

Button·Toggle 같은 액션 Control과 Input·SearchField·Select·Combobox·NumberField·DateField·
DatePicker 같은 단일 행 Outline Frame에 적용합니다. Badge·Checkbox·RadioGroup·Switch처럼
정보·상태 역할과 형태 비율이 다른 요소는 각 역할의 크기 계약을 사용합니다.

## 검토 기준

1. 같은 `size`의 단일 행 Control 외곽 높이가 Surface와 컴포넌트 타입에 관계없이 일치합니까?
2. border·padding·내부 segment가 외곽 높이를 추가로 늘리지 않습니까?
3. 내용 확장형 Control이 같은 크기를 최소 높이로 유지합니까?
4. Typography·Shape·hit target을 Size와 혼합하지 않고 각각의 계약으로 적용합니까?
