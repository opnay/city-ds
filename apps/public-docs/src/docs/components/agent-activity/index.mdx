## 사용 기준

Thinking, 모델 변경, 작업 중단, 도구 실행 로그를 같은 구조로 표시합니다.
이벤트 종류는 고정되어 있지 않으며 아이콘·문구·시간을 children으로 구성합니다.
도구의 입력·결과·오류처럼 뒤늦게 확인할 내용은 Trigger와 Details에 구성하십시오.
pending은 기본 로더 표시만 제어하며 실행이나 데이터 요청을 시작하지 않습니다.
각 part는 render 합성과 ref, className, 이벤트와 ARIA 속성을 지원합니다.

## 접히는 활동 행

활동은 테두리·배경·모서리를 가진 별도 surface가 아니라 대화 흐름 안의 한 행입니다.
상세가 없으면 Indicator, Content, Meta를 Root에 직접 두어 정적인 행으로 표시하십시오.
상세가 있을 때만 세 part를 Trigger 안에 두고 Details를 이어서 배치합니다. 요약 행 전체가 하나의 버튼이 되며 chevron으로 펼침 여부를 나타냅니다. 요약 행과 정적 행은 같은 시작선에 맞추며, 아코디언에만 좌우 여백을 추가하지 않습니다.
Details는 아이콘 뒤 텍스트 열에 맞춰 이어집니다. 상세 안에 입력·결과·오류를 넣되, 실행 취소나 사용자 선택은 질문 UI에 두십시오.
기본은 닫힘입니다. Root의 `open`, `defaultOpen`, `onOpenChange`로 공개 상태를 연결하며, pending이나 서버 상태 갱신이 사용자가 선택한 열림 상태를 바꾸지 않게 하십시오.

## 연속 활동 요약

연속된 파일 읽기·검색·분석처럼 개별 행을 모두 대화 흐름에 노출할 필요가 없을 때는, 상위 Root의 Details 안에 List와 하위 Root를 넣으십시오.
상위 Trigger는 활동 묶음의 요약을, List 안의 Root는 실제 개별 활동을 나타냅니다. 하위 활동도 필요하면 자체 Trigger와 Details를 가질 수 있습니다.
List는 `role="list"`를 제공하고 안의 Root는 기본으로 `role="listitem"`가 됩니다. 현재 진행 중인 행 하나에만 live region을 지정하고, 완료한 하위 활동을 다시 낭독하지 마십시오.

## 접근성

과거 이벤트는 자동 낭독하지 않습니다. 현재 진행 상태가 필요한 경우 소비자가 `role="status"` 또는 `aria-live="polite"`를 지정하십시오.
Indicator는 기본적으로 보조 기술에서 숨겨지므로 진행·중단 의미를 Content에도 표시하십시오.
Trigger는 키보드로 열고 닫을 수 있으며, 클릭 가능한 행은 디자인 시스템의 작은 버튼과 같은 터치 영역과 focus-visible 표시를 가집니다.
긴 문구는 줄바꿈하고, 좁은 화면에서도 시간과 상세를 같은 읽기 순서로 유지하십시오. 가로 스크롤은 코드 같은 상세 내용에만 허용합니다.
기본 진행 애니메이션은 모션 감소 설정에서 멈춥니다. 사용자 아이콘의 애니메이션도 같은 설정을 존중하십시오.
