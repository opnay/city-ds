# Density

Density는 한 영역에서 사용자가 읽고 조작하는 정보량을 조절하는 패턴입니다. 개별 Control의
외곽 크기는 [Control Size](?path=/docs/디자인-패턴-density-control-size--docs), 컴포넌트 내부의
padding과 gap은 [Component Spacing](?path=/docs/디자인-패턴-density-component-spacing--docs)이
각각 책임집니다.

[Layout Spacing](?path=/docs/디자인-패턴-layout-layout-spacing--docs)은 페이지 gutter, 섹션 간격,
grid gap처럼 viewport와 정보 구조에 반응하므로 Density와 분리합니다.

## Density mode

기본값은 `comfortable`입니다. 반복 작업과 비교가 중요하고 포인터 정확도가 충분한 영역에서만
`compact`를 사용하십시오.

`compact`는 화면 크기의 별칭이 아닙니다. 작은 화면에서도 읽기와 터치 정확도가 중요하면
`comfortable`을 유지하십시오.

## 런타임 계약

- 한 작업 영역의 밀도는 `DensityProvider`로 정합니다.
- `DensityProvider`는 `FilterBar`, `Menu`, `Pagination`, `Tabs`, `FileUpload`에 적용됩니다.
- `Table`은 `size`, `EmptyState`는 `density`로 조절합니다.
- 개별 override는 역할이 다른 하위 영역에만 허용합니다.
- Density 변경이 페이지 gutter, 섹션 간격, typography 역할을 자동으로 바꾸면 안 됩니다.

## 적용 순서

1. 반복 빈도, 비교량, 입력 환경을 기준으로 `comfortable | compact`를 선택합니다.
2. Control 역할에 맞는 `size`를 선택합니다.
3. Component Spacing의 container·group·item 간격을 적용합니다.
4. Layout Spacing은 viewport와 정보 구조를 기준으로 별도 적용합니다.

## 검토 기준

1. Density 선택이 단순히 화면이 작다는 이유로 이루어지지 않았습니까?
2. Control Size와 Component Spacing을 같은 값이나 prop으로 취급하지 않습니까?
3. 한 영역 안에서 density가 일관되고 예외의 역할이 명확합니까?
4. compact에서도 읽기, 포커스, hit target이 보존됩니까?
5. viewport 변화가 component density를 암묵적으로 바꾸지 않습니까?
