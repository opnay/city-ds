# Layout Spacing

Layout Spacing은 페이지, 섹션, grid처럼 컴포넌트 밖의 공간 관계를 정의합니다. viewport와 정보
구조에 반응하지만 Control Size나 component density를 자동으로 바꾸지 않습니다.

카드·필드·리스트 내부 spacing은
[Component Spacing](?path=/docs/디자인-패턴-density-component-spacing--docs), 문단 흐름은
[Content Text](?path=/docs/디자인-패턴-typography-content-text--docs)를 따릅니다.

## 소유권 규칙

- Page shell은 좌우 gutter와 페이지 끝 padding을 소유합니다.
- Page content는 주요 section 사이의 gap을 소유합니다.
- Section은 내부 region의 gap을 소유합니다.
- Grid는 column·row gutter를 소유하며 card가 외부 margin으로 보정하지 않습니다.
- 부모와 자식이 같은 위·아래 경계에 padding이나 margin을 동시에 더하지 않습니다.
- Divider는 경계만 표시하며 spacing을 대신 소유하지 않습니다.

## Component Spacing과의 경계

Layout Spacing은 viewport에 따라 page·section 관계를 바꿀 수 있습니다. Component Spacing은
`comfortable | compact` density에 따라 card·field·list 내부를 바꿉니다. 두 축은 독립적으로
조합하십시오.

```text
viewport → page gutter · section gap · grid gutter
density  → card padding · group gap · item gap
size     → Control 외곽 크기 · 내부 padding
```

## 반응형 규칙

- DOM과 키보드 읽기 순서를 먼저 유지하고 CSS로 재배치합니다.
- breakpoint에서는 page gutter와 layout column만 바꾸고 component density는 유지합니다.
- grid를 한 열로 바꿀 때 기존 card 내부 spacing을 다시 정의하지 않습니다.
- 가로 비교가 핵심이면 무조건 세로 stack으로 바꾸지 말고 우선순위·스크롤·crop 중 목적에 맞는
  방법을 선택합니다.

## 검토 기준

1. Page > Section > Region > Component의 spacing 소유자가 하나씩 명확합니까?
2. 부모와 자식이 같은 경계의 간격을 중복해서 만들지 않습니까?
3. page gutter와 주요 정렬선이 header·main·footer에서 일치합니까?
4. breakpoint가 component density와 Control Size를 암묵적으로 바꾸지 않습니까?
5. grid gutter와 card 외부 margin이 중복되지 않습니까?
6. footer 앞 간격을 page shell과 마지막 section이 동시에 만들지 않습니까?
