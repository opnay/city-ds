# Solid

Solid는 atom·molecule의 Surface 축에서 **배경 채움으로 형태와 강조를 만드는 요소**에
적용하는 solid 계열입니다. 액션은 기본 상태부터 채워진 면을 유지하고, 선택 컨트롤은
pressed·checked 상태에서 채워진 면으로 상태를 드러냅니다.

컴포넌트의 기능이 달라도 같은 역할에서는 동일한 fill·foreground·상태 표현을 사용하십시오.
border나 shadow를 겹쳐 형태를 보강하기보다 채움과 전경의 대비만으로 경계를 드러내는 것을
기본으로 합니다.

## 크기 계약

`size`는 Button과 Toggle처럼 텍스트를 담는 단일 행 Solid Control의 **외곽 border-box
높이**를 의미합니다. Surface를 바꿔도 같은 `size`의 높이·padding·radius·아이콘 위치가
달라지지 않아야 합니다.

외곽 높이는 공통 [Control Size](?path=/docs/디자인-패턴-density-control-size--docs) 계약인
`xsm/sm/md/lg/xlg = 24/28/32/36/40px`를 사용합니다.

같은 `size`의 Button과 Toggle은 한 줄에 배치했을 때 위아래 경계와 텍스트 기준선이
일치해야 합니다. Badge·Checkbox·RadioGroup·Switch는 상태 표시 역할에 맞는 별도 크기 비율을
사용하되, Surface 변경 때문에 자체 크기 규칙이 달라져서는 안 됩니다.

Typography는 Surface와 분리합니다. Button·Toggle은
`xsm/sm/md/lg/xlg = 12/12/12/14/14px`의 Control 텍스트를, Badge는 `10/10/12px`의
Compact Status 텍스트를 사용하며 solid·outline·tone이
바뀌어도 이 크기 관계를 유지합니다.

Radius는 Solid가 아니라 Shape 축에서 결정합니다. 직사각형 원자 컴포넌트는 최종 외곽 높이가
20px 이하면 `xs`, 24–40px이면 `sm`을 사용하고, 수량·선택·전환 상태를 나타내는 pill·circle만
`full`을 사용합니다.

## 구성 규칙

- **Action**: Button처럼 즉시 실행되는 주요·위험 액션은 전체 hit target을 하나의 Solid 면으로
  만듭니다. `primary`와 `destructive`는 같은 Surface에서 tone만 달라집니다.
- **Stateful Control**: Toggle처럼 눌림 상태를 가지는 컨트롤은 전체 면을 사용해 상태를
  표현합니다. 기본·pressed 사이에서 geometry를 바꾸지 않습니다.
- **Compact Status**: Badge처럼 짧은 상태·수량을 표시하는 요소는 작은 Solid 면을 사용합니다.
  인터랙션이 없으면 hover·active 표현을 추가하지 않습니다.
- **State Indicator**: Checkbox·RadioGroup·Switch는 선택 영역 전체가 아니라 indicator나 track의
  checked 상태에만 Solid를 사용합니다. 상태가 해제되면 원래 Surface로 돌아갑니다.

Solid는 Surface 방식이고 tone은 의미입니다. 현재 Button의 `primary`와 `destructive`는 두 축을
합친 preset이며, Badge는 `appearance="solid"`와 `tone`을 분리합니다. API 형태가 달라도 같은
tone의 fill과 foreground 관계는 일관되어야 합니다.

## 색상 대비 규칙

- white·neutral 계열 Solid는 fill 밝기에 따라 밝거나 어두운 전경을 사용할 수 있습니다.
- 그 외 유색 Solid는 전경을 `neutral-50`으로 고정하고, 일반 텍스트 대비 4.5:1 이상을
  만족하는 어두운 fill 단계만 사용하십시오.
- 더 밝은 유색 배경이 필요하면 Solid의 전경을 어둡게 바꾸지 말고 Subtle 또는 Outline
  Surface를 사용하십시오.

## 상호작용 위임 규칙

Solid는 상태 소유자에 따라 두 방식으로 구분합니다.

- **Persistent Surface**: Button·Solid Toggle처럼 기본 상태부터 면이 채워진 컨트롤은 전체 면이
  하나의 hit target입니다. 텍스트나 아이콘만 별도 hover·active를 갖거나 별도 탭 정지점이
  되어서는 안 됩니다.
- **State-driven Surface**: Checkbox·RadioGroup·Switch처럼 선택 상태에서만 Solid가 되는
  컨트롤은 checked·pressed 상태를 소유한 root가 fill을 제어합니다. 레이블이 hit target을
  확장할 수는 있지만, 레이블 자체가 별도의 Solid 면이나 중복 동작을 만들면 안 됩니다.

Badge처럼 정적인 Solid는 상태를 전달할 뿐 동작을 암시하지 않아야 합니다. 링크나 버튼으로
동작해야 한다면 해당 인터랙티브 컴포넌트의 hover·active·focus 규칙을 함께 적용하십시오.

## 상태 규칙

- Persistent Surface는 기본 상태에서도 fill을 유지하십시오. hover에서만 면이 생기는 표현은
  Ghost입니다.
- hover와 active는 같은 tone 안에서 fill의 명도만 조정하고 border나 shadow를 새로 만들지
  마십시오.
- pressed와 checked는 역할에 따라 전체 control 또는 indicator가 Solid를 소유하도록
  일관되게 표현하십시오.
- focus-visible은 외곽 ring으로 표시하고 컴포넌트 크기나 주변 배치를 바꾸지 않아야 합니다.
- disabled는 fill과 foreground를 하나의 비활성 단위로 낮추고 텍스트만 따로 흐리게 하지
  마십시오.
- 정적 Badge에는 hover·active·focus 상태를 만들지 마십시오.

## 적용 범위

적용 대상은 Button의 주요·위험 액션, Solid Toggle, Badge의 짧은 상태·수량,
Checkbox·RadioGroup·Switch의 checked·pressed indicator처럼 채움으로 강조나 선택 상태를
표현하는 요소입니다.

Input, Select, Combobox처럼 값을 담고 편집하는 컨트롤은 Outline Frame을 사용합니다. 낮은
우선순위의 액션은 Subtle·Outline·Ghost를 사용하고, 넓은 Alert는 Subtle 또는 Outline을
사용합니다. Toast는 appearance 없이 background 92%와 tone 원색 8%를 혼합한 배경, tone 원색
border·텍스트를 사용합니다. Popup·Dialog의 떠 있는 관계는 Solid가 아니라 elevation 축으로
구분합니다.

## 검토 기준

1. 기본 상태부터 채워져야 하는 Persistent Surface와 선택 상태에서만 채워지는 State-driven
   Surface가 구분됩니까?
2. 같은 `size`의 Solid Control 외곽 높이·padding·radius가 다른 Surface와 일치합니까?
3. 유색 Solid가 `neutral-50` 전경과 4.5:1 이상 대비를 이루며 컴포넌트 사이에서 일관됩니까?
4. 채움만으로 형태가 보이며 불필요한 border·shadow가 중복되지 않습니까?
5. Persistent Surface의 전체 면이 하나의 hit target과 상태 소유자로 동작합니까?
6. State-driven Surface의 root와 label이 중복 동작이나 중복 Surface를 만들지 않습니까?
7. hover·active·pressed·checked·focus·disabled가 geometry를 바꾸지 않고 구분됩니까?
8. Solid가 낮은 우선순위의 액션이나 넓은 feedback surface를 불필요하게 지배하지 않습니까?
