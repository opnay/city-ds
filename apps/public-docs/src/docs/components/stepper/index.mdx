## 사용 기준

Stepper는 가입, 연결 설정, 가져오기처럼 시작과 끝이 정해진 작업의 단계를 표시합니다.
독립된 화면 전환에는 Tabs를, 처리 비율에는 Progress를 사용하십시오.
Root 안에 Item을 순서대로 배치하고 Indicator와 Content를 조합하십시오.

## 배치

가로 배치는 좁은 화면에서도 유지됩니다. 단계 제목을 짧게 작성하십시오.
Description은 세로 배치에서 완료한 단계의 입력·결과 요약을 표시합니다. 현재 단계와 대기 단계에는 표시하지 않습니다.
예를 들어 기본 정보 단계를 마치면 입력한 프로젝트 이름을, 팀원 초대를 마치면 초대 이메일이나 인원수를 요약하십시오.
현재 수행할 작업의 안내와 오류 복구 방법은 현재 단계 본문에서 제공하십시오.

## 상태와 이동

현재 위치는 `current`, 완료·오류 여부는 `status`로 지정하십시오. 현재 단계에서도 오류를 표시할 수 있습니다.
단계 순서만으로 완료를 추정하지 않습니다. 전체 작업이 끝나면 모든 항목의 current를 해제하고 완료된 항목에 completed를 지정하십시오.
이동 가능한 단계에는 Trigger를, 그 외에는 Title을 사용하십시오. Trigger의 disabled는 이동만 제한하며 단계 상태를 바꾸지 않습니다.

입력 보존, 검증, 저장 요청, 중복 제출 방지와 단계 이동 권한은 소비 화면에서 처리하십시오.
비동기 저장에 성공한 뒤 단계를 변경하고, 실패하면 현재 단계와 입력을 유지하십시오.

## 접근성

순서 목록과 `aria-current="step"`으로 현재 위치를 표현합니다. Tabs나 progressbar 역할을 추가하지 않습니다.
Root에 작업 이름을 지정하고 current는 목록당 하나만 사용하십시오.
완료·오류 상태는 숨겨진 statusLabel로도 전달됩니다. 화면 언어에 맞는 문구와 오류를 해결할 수 있는 설명을 제공하십시오.
Trigger는 Tab으로 이동하고 Enter·Space로 실행하는 일반 버튼입니다. 화살표 키로 단계를 바꾸지 않습니다.
단계 본문을 교체하는 화면에서는 새 제목으로 포커스를 이동하거나 변경을 알리고, 이전 단계의 입력을 유지하십시오.

[WAI 다단계 폼 안내](https://www.w3.org/WAI/tutorials/forms/multi-page/)와 [aria-current 기법](https://www.w3.org/WAI/WCAG21/Techniques/aria/ARIA26)을 따릅니다.

실제 생성·배포 요청과 권한 검증은 소비자가 연결합니다.
