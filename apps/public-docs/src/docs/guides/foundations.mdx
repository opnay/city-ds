## 테마의 소유자

city-ds에는 `CityProvider`가 없습니다. 애플리케이션의 문서 루트에 `data-theme`을
설정하는 방식이 테마 계약입니다. 따라서 라우터, 저장소, 시스템 설정을 어디에서 읽고
저장할지는 소비자 앱이 결정하고, city-ds는 `light`, `dark`, 속성 없음(system)을
해석합니다.

```tsx
import type { CityTheme } from '@opnay/city-ds-react';

function setTheme(theme: CityTheme) {
  if (theme === 'system') {
    delete document.documentElement.dataset.theme;
  } else {
    document.documentElement.dataset.theme = theme;
  }
}
```

테마를 바꾸는 요소는 현재 값과 선택지를 텍스트로 알 수 있게 하십시오. 시스템 설정을
따르는 경우에도 선택 UI에는 `system`이라는 명시적인 값이 필요합니다.

## 토큰을 사용하십시오

공개 토큰은 모두 `--city-` 접두사를 사용합니다. 앱 CSS는 패키지 CSS 뒤에 로드하고,
필요한 값만 덮어쓰십시오. 임의 색상, 그림자, 간격을 반복해서 추가하기보다 의미 있는
토큰을 먼저 선택하면 light/dark 전환과 화면 간 일관성이 유지됩니다.

```css
:root {
  --city-radius-md: 0.5rem;
}

[data-theme='light'] {
  --city-color-primary: oklch(0.32 0.01 286);
}
```

| 범주         | 대표 토큰                                                     | 사용할 때               |
| ------------ | ------------------------------------------------------------- | ----------------------- |
| 색상         | `--city-color-background`, `--city-color-primary`             | 표면, 텍스트, 의미 상태 |
| 간격         | `--city-space-2`, `--city-space-6`                            | 영역과 요소의 관계      |
| 타이포그래피 | `--city-font-size-sm`, `--city-font-weight-medium`            | 정보 위계               |
| 형태와 효과  | `--city-radius-md`, `--city-shadow-panel`                     | 경계와 표면             |
| 모션         | `--city-duration-normal`, `--city-easing-standard`            | 전환과 상태 변화        |
| 제어         | `--city-control-sm`, `--city-control-md`, `--city-control-lg` | 같은 행의 control 크기  |

토큰 재정의는 앱 전체의 의도된 변형에만 사용하십시오. 한 컴포넌트의 예외를 해결하려고
전역 토큰을 바꾸면 다른 화면의 대비와 밀도도 함께 바뀔 수 있습니다.

## 크기와 밀도

일반 control의 크기는 `sm`, `md`, `lg`이며 기본값은 `md`입니다. 같은 폼 행, 툴바,
선택 그룹에서는 같은 크기를 유지하십시오. `sm`과 `lg`는 우선순위가 아니라 공간과
정보 밀도의 선택입니다.

반복 작업과 비교가 중요한 한 영역만 `DensityProvider`로 `compact`로 바꾸십시오.
작은 화면이라는 이유만으로 compact를 강제하지 마십시오. 터치 환경에서는 읽기와
누르기 정확도가 더 중요할 수 있습니다.

```tsx
import { DensityProvider } from '@opnay/city-ds-react/density-provider';
import { FilterBar } from '@opnay/city-ds-react/filter-bar';
import { Pagination } from '@opnay/city-ds-react/pagination';

export function CompactResults() {
  return (
    <DensityProvider density="compact">
      <FilterBar aria-label="결과 필터">{/* filters */}</FilterBar>
      <Pagination.Root>{/* pagination items */}</Pagination.Root>
    </DensityProvider>
  );
}
```

`DensityProvider`는 `FilterBar`, `Menu`, `Pagination`, `Tabs`, `FileUpload`에 적용됩니다.
`Table`은 `size`, `EmptyState`는 `density`로 각각 조절하십시오. 개별 control의
밀도를 섞기보다 역할이 다른 하위 영역을 분리하십시오.

## 전역 스타일 범위

`styles.css`는 패키지의 앱 기반 스타일입니다. 앱 진입점에서 한 번 가져오고, 앱의
기존 reset·기본 요소 스타일과 충돌하는지 통합 화면에서 확인하십시오. 토큰만 연결하는
특수 환경은 `theme.css`를 사용하되, city-ds 컴포넌트의 스타일이 필요하면 다시
`styles.css`로 전환하십시오.

레이아웃에는 앱 고유 클래스를 사용하고 색, 간격, 글꼴 값은 `--city-*` 토큰에
연결하십시오. public docs처럼 별도 UI를 만들 때도 패키지 전역 선택자나 컴포넌트 내부
구조에 의존하지 않아야 업데이트에 안전합니다.
