# 워크플로우 조회 패턴

실행을 비교하고 실패 원인과 재시도 경위를 조사하는 읽기 중심 패턴입니다. `packages/react/DESIGN.md`의 목록 상세 조회, 콘텐츠 선택, 피드백, 간격 규칙을 적용합니다. 실행 설정·승인·배포 준비는 이 세 블록의 범위가 아닙니다.

## 조회 흐름과 컴포넌트 선택

| 블록             | 사용자 목적             | 정보 위계                                                                    |
| ---------------- | ----------------------- | ---------------------------------------------------------------------------- |
| 실행 기록        | 대상 실행 찾기          | 검색·조건 필터 → 결과 수 → 워크플로우·실행 ID·버전 → 환경·상태·실행자·시각   |
| 실행 상세        | 원인과 작업 로그 확인   | 워크플로우·상태 → 실패 사건 Alert → DataList → 작업 로그 / 이벤트 이력 Tabs  |
| 실행 이벤트 이력 | 실패 전후와 재시도 조사 | 실행 식별 정보 → 날짜·시간대 → 사건 제목·시각 → 설명·실행자 → 관련 로그 액션 |

- 목록 상세는 Drawer로 열어 검색·필터 맥락을 유지합니다. Escape 또는 닫기 후 선택했던 실행 버튼에 초점을 복구합니다. 소비 앱은 `onView(id)`를 상세 경로에도 연결할 수 있습니다.
- 실행 상세와 이벤트 이력은 선택한 실행에 속한 패널입니다. 이벤트 블록에는 `run`의 실행 ID·버전·환경·워크플로우를 함께 전달합니다. 독립 상세 페이지에서는 소비 앱이 실행 기록으로 돌아가는 경로와 선택 상태를 제공합니다.
- 작업별 콘텐츠 선택은 Tabs로 표현합니다. 작업 상태 Badge는 서버 결과이며 선택 상태와 독립적입니다. Stepper는 순서 있는 절차를 안내할 때 사용하므로 이 로그 선택기에는 사용하지 않습니다.
- 최초 로그는 실패·실행 중 작업을 우선 선택하고, 모두 종료했으면 마지막 작업을 선택합니다. 다른 실행을 조회하면 선택과 복사 피드백을 초기화합니다.
- 이벤트의 로그 액션은 작업 로그 탭을 열고 대상 로그 영역으로 초점을 옮깁니다. 존재하지 않는 작업 ID에는 액션을 노출하지 않습니다.
- 독립 이벤트 미리보기는 로그 선택 뒤 대상 작업 로그를 표시하고 이벤트 이력으로 돌아갈 때 선택한 로그 버튼에 초점을 되돌립니다. 소비 앱은 `onViewLogs(stageId)`를 실제 실행 상세의 로그 경로에 연결합니다.

## 표면·간격·반응형

- 독립 블록의 Panel이 외곽 간격을 소유합니다. Drawer에서는 블록의 중복 테두리·패딩을 제거하고 Drawer.Content가 스크롤을 소유합니다.
- 실행 기록은 결과에 직접 연결된 FilterBar를 사용합니다. 별도 배경과 패딩 없이 표 바로 위에 검색·조건·결과 수·초기화를 모읍니다. 필터 양 끝을 블록 헤더와 Table 영역의 바깥 경계에 맞추며, 셀 내부 여백을 필터의 래퍼에 추가하지 않습니다.
- 검색 입력은 남은 폭을 사용하고 좁아지면 선택 조건과 줄을 나눕니다. 컨트롤 크기는 유지하며 조건이 없으면 초기화를 비활성화합니다. 로딩·조회 오류 중에는 결과 수를 표시하지 않습니다.
- FilterBar의 조건 라벨은 `sr-only`로 숨기고 각 입력과의 접근성 연결을 유지합니다. 검색 placeholder와 선택 값으로 조건을 표시합니다.
- Table은 비교 열을 보존하고 DataTableRegion 안에서 가로 스크롤합니다. 좁은 화면 때문에 컨트롤 밀도를 바꾸지 않습니다.
- 메타정보는 컨테이너 폭에 따라 2열 또는 3열입니다. 작업 탭은 줄바꿈하고 로그는 최대 높이와 독립 스크롤을 가집니다. 긴 식별 정보는 줄바꿈하고 원문 로그는 공백과 줄 구조를 보존합니다.
- 제목·라벨·보조 정보는 기존 typography 역할을 사용합니다. 로그만 monospace를 사용합니다.

## 상태와 데이터 계약

- 초기 로딩은 표 행·메타정보·이벤트 구조에 대응하는 Skeleton입니다. 로딩·조회 오류는 이전 데이터를 대체합니다.
- 오류는 Alert의 원인 설명과 소비자가 제공한 재조회 액션으로 표현합니다. 실행 실패 사건은 상세 상단에 보존하며 실제 재실행을 임의로 수행하지 않습니다.
- EmptyState는 미실행, 검색 결과 없음, 작업·로그·이벤트 없음의 이유를 구분합니다. 검색 결과 없음에는 필터 초기화를 제공합니다.
- Timeline은 동일한 24px indicator·14px SVG를 사용합니다. 성공·오류·경고는 CircleCheck·CircleAlert·TriangleAlert, 대기는 정적 Clock, 실행 중은 LoaderCircle, 재시도는 RotateCcw입니다. 모션 감소 환경에서는 회전을 제거합니다.
- 블록은 의미 색상 CSS 변수를 사용하지만 Timeline의 공개 `color`는 자유 CSS 색상값을 유지합니다. 상태는 색상 외에 아이콘·문구·접근 가능한 이름으로 전달합니다.
- 이벤트 배열 순서를 보존하면서 연속된 KST 날짜별로 묶습니다. 각 `time.dateTime`에는 원본 ISO 시각을 보존합니다. 재시도는 이전 실패를 덮어쓰지 않습니다.
- 데이터 조회·권한·민감 로그 제거·폴링·서버 검색·페이지 이동·실제 실행은 소비자가 소유합니다. 예제는 고정 샘플이며 네트워크 부수 효과가 없습니다.
