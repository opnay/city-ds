# 워크플로우 조회 패턴

실행 기록에서 대상을 찾고, 상세에서 단계 로그와 시간순 이벤트를 확인하는 읽기 중심 패턴입니다. 실제 실행·재시도·승인 작업은 소비 앱이 연결합니다.

## 구성과 정보 위계

- 실행 기록은 FilterBar와 Table로 환경·상태·실행자·시각을 비교합니다. 긴 표는 DataTableRegion 안에서 스크롤합니다.
- 실행 상세는 하나의 Panel 안에 실행 메타정보, 단계·로그, 이벤트 이력을 배치합니다. 하위 영역에 Panel 테두리를 반복하지 않습니다.
- Stepper는 정해진 단계의 현재 상태와 로그 선택을, Timeline은 발생한 사건의 순서를 표현합니다. 로그를 선택해도 실행 상태는 바뀌지 않습니다.
- 이벤트는 제목 → 발생 시각·실행자 → 설명 → 로그 액션 순서로 읽습니다. 좁은 화면에서는 시각을 제목 아래에 배치합니다.

## 상태와 아이콘

- Timeline의 24px indicator와 14px SVG 크기를 공통으로 사용합니다. 아이콘별 크기 보정으로 맞추지 않습니다.
- 성공·오류·경고는 Alert·Toast와 같은 CircleCheck·CircleAlert·TriangleAlert 계열을 사용합니다. 작은 내부 획만 가진 Check·X와 시계·로더를 섞어 시각적 크기가 달라지지 않게 합니다.
- 대기는 정적인 Clock, 실행 중은 LoaderCircle, 재시도 사건은 RotateCcw로 표현합니다. 모션 감소 설정에서는 로더의 회전만 제거합니다.
- 성공·실행 중·오류·경고는 success·info·destructive·warning 의미 토큰에 연결합니다. Timeline에는 CSS color 값으로, Badge에는 기존 tone API로 전달합니다.
- 아이콘 형태와 사건 제목으로 상태를 구분하고, 스크린 리더에는 상태 이름을 제공합니다. 제목과 같은 상태를 별도 줄에 반복하지 않습니다.

## 데이터와 접근성

- 이벤트 ID와 시간대가 포함된 ISO 시각을 전달하고, 배열 순서를 그대로 표시합니다. 재시도는 기존 실패 기록을 지우지 않고 새 사건으로 추가합니다.
- 존재하는 단계의 로그만 연결합니다. 이벤트의 로그 액션은 대상 로그 영역으로 초점을 이동합니다.
- 초기 조회는 Skeleton, 빈 결과는 안내 문구, 조회 실패는 오류 문구와 재조회 액션으로 구분합니다. 로딩·오류 중에는 이전 이벤트를 함께 표시하지 않습니다.
- 상태는 색상에만 의존하지 않으며 라이트·다크 테마, 모바일, 키보드 이동, 모션 감소 설정에서 확인합니다.
